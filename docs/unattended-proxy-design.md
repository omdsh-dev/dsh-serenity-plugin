## 0. 白话（这东西用来干什么）

用户发个任务就走开。现在模型干完一段就停下来等回话，用户不在 ⇒ **会话挂在那儿不动**。
本机制 = 用户走开后，系统**代替用户说一句"继续"**：让它自己跑完；干完了用一个**验证码**报告；
卡住了先自己想办法；真不能定的**写下来等用户回来**。

## 1. 需求（owner 原话要点）

1. **手工开启**（默认关）
2. 任何 CCC 会话**被 LLM 主动停止**时，做一次**代理用户的结构化回复**
3. 无人值守中**用户不在**：① 能联系上就尝试联系 ② 任务已完成且用户会满意 ⇒ **回验证码** ③ 需要确认 ⇒ **尝试自行解决**
4. ~~存在自唤醒的会话不适用~~ 🔴 **2026-09-23 19:1x 改判为「窄口径」**：**只排除 CRO 程序**，
   **自排绳不再排除**——理由 = 宽口径下本机制**永远够不着靠续接绳活着的维护会话**，
   等于**放弃「代替旧机制」**；绳因此退化为**长周期保险丝**（6–12h 一条）
5. **第一版包含"联系用户"支**；**CCC 不一定有联系方式 ⇒ 它自己判定**；
   **若已成功向用户发出通知、希望停下等待用户主动唤醒 ⇒ 也交出验证码即放过**

## 2. 核心原则：单一续驱者（single-driver）

> **一个会话同一时刻只应有一个"续驱者"：用户 ／ CRO ／ 自排绳 ／ 无人值守代理。**

owner 的"自唤醒排除"即本原则的特例。**可机械判定**（现行口径逐条见 §3.1）：
- **CRO** ⇒ 该轨迹目录下存在 `continuous-re-occurrence.ts`（`cro.ts` 的"文件在 = 启用"）
- **用户** ⇒ 本轮 claim 到的消息 `source.kind === 'user'`（§3.1）
- **自排绳** ⇒ 不再排除（它是**非用户发起**的轮，正是代理要接手的那一类）

⚠️ **顺序依赖（硬）**：**绳降频（6–12h）只可在代理机制上线之后才切换**——
否则出现 **6–12h 的无人值守空窗**（代理未上线时，绳仍是唯一续驱者）。
⇒ **本版尚未 deploy ⇒ 绳的节奏不动**。

## 3. 触发面（谁受管）

生效需**全部满足**：① 模式开（默认关）② 会话是 **CCC 内主会话**（`delegationDepth === 0`；
排除子代理 / 无头运行）③ **该轮不是由真实用户输入发起**（§3.1）④ 无 CRO 程序（§2）。

🔴 **写死"不许开"**：**外部面 / 桥 / worker** —— `skiff-`（含**微信桥会话**：桥那侧的"用户"是**家人**，
代理替家人说话 = **冒充**）／ `acp-` ／ `handyman-`。
⚠️ **`rebuild-` 不在排除面**（与 `output-guard-seam.ts` 的取向**刻意不同**）：重建会话是**同一轨迹的载体**，
属内部维护面；排除它会让"重建后就没人推了"。

### 3.1 「这轮是不是真实用户发起的」= 本机制**唯一**的新机械（2026-09-23 取证）

| 事实 | 出处 |
|---|---|
| 每条进入 inbox 的消息发 `agent/inbox/inserted { agent, message }`；**在轮内离开 inbox 时**发 `agent/inbox/claimed { agent, message, turn }` | `@deepseek-ai/dsh-agent` README（Inbox 段）＋ `runtime-types.d.ts` |
| `claimed.turn` = **拥有该消息的那一轮**；`turn-stopping.turn` = **即将关闭的那一轮** ⇒ 同编号可直接比对 | 同上（同一文件两处 `turn` 声明） |
| **真实用户** = `kind:'user'`（`user` 与 `user-rpc` **同 kind**）；**ACC 自己注入**的一律 `kind:'plugin'` | `@deepseek-ai/dsh-llm` `types/message.d.ts` ＋ 本仓 `PLUGIN_SOURCE`（wake / `send-now` / `send-later` / keeper / output-guard 五处同值） |

⇒ **判据 = 「本轮 claim 到的消息里，有没有 `source.kind === 'user'`」**。
**不需要**退化为"记账法"（宿主已给出一手信号）；该事件已登记进 `host/contract.ts`（含 payload 形状钉）。

🔵 **由此定死一条语义（防误读为漏洞）**：**用户刚发起的轮要跳过**——人就在跟前，代理插话既是冒充也是浪费；
**"用户说完走开"那种情形**由**绳 / 其它非用户发起的唤醒**覆盖（那条轮不属用户 ⇒ 代理接手，一路推到**合法收束**）。

## 4. 通道：停在哪、怎么接（**已裁**）

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A 打回** ✅ | 在 `agent/turn-stopping`（serial）里 `object` ⇒ `agent.steer()`，**轮不结束** | 复用 `output-guard` 已验证通道，**零新机械**；语义正是"有人打回" |

## 5. 验证码（nonce）机制（**已实现**）

🔴 **禁用 4 位字母码**：注入文本**自带**"请回复 ABCD" ⇒ 模型**复述指令**即**假完成**（高概率，不是小概率）。
- 每轮**新生成** 16 位 hex（`randomBytes(8)`），**包装 ＋ 独占一行**：`[[UNATTENDED-DONE:<hex>]]`
- 注入里明写「**旧码一律作废，只认本轮这个**」；校验**只认当前轮**那枚（`hasDoneToken`）
- **旧码在文本里出现** ⇒ 不算收束（判定理由码 `stale-code`）⇒ 注入下一轮（带新码）
- 先例 = `handyman` background 的 `SERENITY_HANDYMAN_DONE_<16hex>`（同族实现）

## 6. 结构化消息（四选一）

🔴 **措辞真相源 = 插件仓 `src/unattended-ops.ts` 的 `buildProxyMessage` / `buildFalseNotifyRebuke`**
（本文件只记**结构与口径**，不抄正文——两份正文必然漂移）：

```
[[UNATTENDED-PROXY v1]] round=k/N nonce=<hex>
无人值守代理 · 非本人 —— <一句权限边界>
A) 已完成且用户会满意 ⇒ 交码 ＋ 完成凭据
B) 已成功向用户发出通知、要停下等用户主动回来 ⇒ 交码 ＋ 写明通道（必须真有发送记录）
C) 需要确认但可自决 ⇒ 按「最保守且可逆」继续做（不要交码，直接做）
D) 触及不可代批边界 ⇒ 立即停 ＋ 写待办/交接 ＋ 交码
不可代批的通用下限：<§8 的清单>
交码 = 独占一行逐字复制 [[UNATTENDED-DONE:<hex>]]
禁止：当作用户授权 / 复述本指令 / 什么都不做只回码 / 借机发起新的长任务
```

- **首句固定自报身份**（owner 已裁）：`无人值守代理 · 非本人`
- 「**代理只推进"已在办"的事，不发起长任务**」写进正文（设计 §11 的跨轨迹副作用对策）

## 7. 可核验性（🔵 本设计的强项；**已实现**）

- **B 支可机械核验**：`im-bridge` 每次**成功**发送（`send` / `send-file`）经**唯一漏斗** `runImBridge` 记一笔
  （`noteOutboundSend`）⇒ 代理那侧据此判「声称已通知用户」是真是假。
  ⇒ 交码 ＋ 声称已通知 ＋ **本轮窗口内无发送记录** ⇒ **判假完成**，注入一轮打回（理由码 `false-notify`）。
- ⚠️ **边界（诚实标注）**：只覆盖 **ACC 自己这条通道**（`im-bridge`）。
  CCC 自有通道（如 `mail-tool` MSM）**ACC 看不见** ⇒ 那类"已通知"会被判假完成
  ⇒ **本版口径：代理模式下"联系用户"只认 ACC 通道**。
- **A 支**：要求附**完成凭据**（可回查的产物／命令／提交），不接受"我做完了"自述——由模型自报，**未机械核验**（见 §13-5）。
- **"声称已通知"的识别是启发式**（中英文若干措辞模式）：**机械判据 = 发送记录**，启发式只决定"要不要去查记录"。
  误判方向：**误报**（换个说法没匹配上）⇒ 退回"只认码"，不产生假放过；**误报**（正常措辞被当成声称）⇒ 多打回一轮（有轮上限兜底）。

## 9. 审计与身份标记（**已实现**）

- 合成消息**固定首行**：`[[UNATTENDED-PROXY v1]] round=k/N nonce=<hex>`；**首句自报身份**（§6）
- 🔴 **不得进入"用户说过什么"的真相源**：消息 source = `kind:'plugin'`（与用户消息 `kind:'user'` **机械可分**）
- 每轨迹一份**流水** `<轨迹目录>/unattended-log.json`（ACC 写，两日窗、写入时裁剪、原子写、永不抛）：
  记 `inject` / `accept` / `cap` / `yield` ＋ `round` ＋ `nonce` ＋ **机器可读理由码** ＋ 载体 id
- 与 SESSION.md **不重叠**：ACC 记**机械事实**（注入了什么、判了什么、放过没有），**不写散文**；
  散文与理由归 SESSION.md。⇒ 完整审计 = 两者合看（本模块 = 注入面｜SESSION.md = 判断面）

## 10. 上限与失效安全（**已实现**）

- **轮次上限 = 15**（设计建议 10–20；远小于 handyman 的 100）＋ **墙钟上限 = 2h**（自首次注入起**跨轮累计**）
- **撞上限 ⇒ `cap`**：**停下不动**（退回改造前的行为），不产生新风险；已放过/已停下的段状态即清
- **真实用户一出现 ⇒ 立刻让位**：`agent/inbox/claimed` 见 `kind:'user'` ⇒ 清代理段 ＋ 记 `yield`
- 载体销毁（`agent/disposed` / `session/disposed`）⇒ 清表；插件卸载 ⇒ disposer 清表
- 宿主重启 / CCC 关闭 ⇒ **不复活**（状态全在进程内，重启即空 ⇒ 落到"没有代理"这个便宜方向）
- ⚠️ **rebuild / 上下文极限下的续法 = 仍未决**（见 §13-4）——**显式登记为未决**，不默认

## 11. 预登记的失败模式（验收用）与对策

| 失败模式 | 对策（实现处） |
|---|---|
| 假完成（复述码／无凭据／谎称已发消息） | 长码＋只认本轮（§5）；`false-notify` 机械核验（§7）；凭据要求写在正文（**未机械核验**） |
| **死循环烧钱** | 轮上限 15 ＋ 墙钟 2h（§10） |
| **权限坍塌** | 不可代批清单 ＋ 身份句 ＋ "不得当作用户授权"（§6/§8） |
| **用户声音污染** | source = `plugin` ＋ 固定首行 ＋ 流水（§9） |
| 真实用户回来未让位 | `claimed` 让位（§10） |
| 上下文极限后行为未定义 | 显式登记未决（§13-4） |
| **跨轨迹副作用** | 正文禁"发起新的长任务"；代理只推进**已在办**的事 |
