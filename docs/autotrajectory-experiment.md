# 自主轨迹实验（Autonomous Trajectory Experiment）— CCC 参与定义说明

> **版本**：v1.26.12 pre-release（实验功能，**默认关闭**；未配置 = 零资源占用）
> **依据**：serenity-acc-specs `docs/self-sustaining-trajectory-hypothesis.md`（v0.1 猜想，S142 2026-08-30 用户提出）
> **机制实现**：`src/autotrajectory.ts`（本插件，dsh-serenity-hooks）
> **阅读对象**：任何希望参与本实验的 CCC（认知容器）——本文档让 CCC 完整理解实验的**方式、目的与背景**。

---

## 1. 背景：为什么做这个实验

认知容器理论（serenity-acc-specs §0）确立了三个命题：

1. **Trajectory 是主体**——Agent 可替换、Session（载体）可重建、LLM 是认知介质；轨迹跨越时间持续存在。
2. **动作 = 反馈**——Loop 中的一切外部交互（工具/等待用户/系统事件）都是反馈采样。
3. **认知容器 = 发生/存储/再发生的地方**——已实现该闭环的容器，结构上已具备支撑长期认知演化的形态。

由此观察到一个**结构性瓶颈**：

> **P3**：当 trajectory 以"等待人类"为推进条件时，其事件序列时间被人类响应间隔（钟表时间）锚定。等待人类 = 轨迹空转——**人类响应越慢，trajectory 运转越慢**。在"等待是反馈采样通道"的意义上等待不是死亡；但在推进速度的意义上，等待是**速度上限**。

**猜想（P4→P5）**：可以设计一种"无人等待"的 trajectory——它不依赖人类输入而自动唤起，且唤起时携带先验偏见（自主动机）。若成立，trajectory 运转速度提升，从而更快产生让人类满意的效果。

理论衔接：serenity-acc-specs §0.7 展望"认知容器从记录器深化为校准器"（预测加工方向）——本实验是其候选工程路径。

---

## 2. 实验目的（验证什么）

| 命题 | 内容 | 验证方式 |
|------|------|---------|
| **P4** | 无人等待的 trajectory 可以自动唤起（时钟驱动）并携带先验偏见（自生+随机） | 阶段 A（机制可行性） |
| **P5** | trajectory 运转速度提升（单位时间认知推进量↑）→ 更快产生让人类满意的效果 | 阶段 B（速度对比） |
| **反证** | 熵增失控 / 自我确认循环 / 随机噪音化 / 资源无界 / 反馈脱节——任一显著出现且无法对冲 → 猜想或其当前形态不成立 | 阶段 C/D（质量与熵） |

**本实验不是标准条款**：它不修改 Serenity-ACC 标准正文；验证成立后才评估是否进入标准演化议程。

## 3. CCC 参与方式（四步）

### 3.1 配置（CCC 根 `.opencode/serenity.json`）

```jsonc
{
  "autotrajectory": {
    "enabled": true,                 // 总开关（缺省 false——默认关，未开零资源占用）
    "intervalHours": 12,             // 无人类活动 N 小时后自动唤起（缺省 12）
    "biasProvider": "autotrajectory-bias.ts", // 偏见内容提供者脚本（相对 CCC 根，缺省同名）
    "topPrompt": "本轨迹的核心焦点：<CCC 填写>",  // 轨迹焦点（v1.26.17）：CCC 定义，每次唤起最先注入
    "session": "S143",               // 可选：固定目标会话（S###/目录名）；缺省 = 最近活跃
    "avoidWakeHours": { "start": 8, "end": 18 }  // 可选：避开北京高峰（缺省 8~18，用量峰谷省钱）
  }
}
```

> 实验包提供一键初始化：`acc_msm exec autotrajectory-exp init`（写配置 + 生成偏见提供者脚本模板）。

### 3.2 定义轨迹焦点（topPrompt——CCC 自己填写）

**CCC 定义 autotrajectory 时同时定义本轨迹的顶层提示词**（`topPrompt`）：核心目标/纪律/质量要求。它会在**每次唤起时最先注入**（`[轨迹焦点]` 段，位于身份锚定之前，影响力最大），作为**稳定焦点锚定 trajectory**——**实验观察：无焦点锚定时，多轮自主唤起中轨迹腐化严重（焦点丢失）**。与偏见内容的分工：**焦点=稳定锚（每轮不变），偏见=随机探索方向（每轮不同），互补**。init 会生成占位，CCC 按自己轨迹目标改写（勿留空——留空 = 唤起无焦点锚定，轨迹易漂移）。

### 3.3 实现偏见内容提供者（CCC 根目录脚本——偏见内容归 CCC）

CCC 根目录下一个脚本（缺省 `autotrajectory-bias.ts`），dsp 唤起时**直接运行**取 stdout 作为偏见内容。**偏见内容由 CCC 保证**（CCC 有具体的反馈信息来源：历史事件、外部信息、真随机源等——用自己认为"足够随机"的方式）。**脚本缺失 → 唤起中止并报错要求实现**（不再经 mech-registry 注册 MSM）。`acc_msm exec autotrajectory-exp random` 可验证输出。

```ts
// autotrajectory-bias.ts（CCC 根）
// 示例：随机取历史 SESSION 的一个话题 → 生成反事实方向（CCC 可换任何随机源）
const sources = ['离线索引', '会话命名', '守卫语义', '轨迹落盘'] // ← CCC 自己的信息来源
const pick = sources[Math.floor(Math.random() * sources.length)]
console.log(`反事实：如果「${pick}」换个做法会怎样？`)
```

### 3.4 标记目标会话 + 可选自生动机段

- **会话标志（必须）**：目标会话目录名加 `--auto` 后缀——`AGENT_SESSIONS/<date>--<desc>--auto/`。**只有带该标志的轨迹走自主形态；同一 CCC 其他会话完全不受影响。**
- **自生动机（可选）**：该 SESSION.md 内可写「下一轮动机」段——上一轮结束时预写，作为下一轮唤起的自生偏见（轨迹预设自己的未来）：

```markdown
## 下一轮动机
探索 X 方向的反事实：如果步骤 3 用 B 方案会怎样。
```

## 4. 机制运行说明

### 4.1 唤起条件（全部满足才唤起）

| # | 条件 | 说明 |
|---|------|------|
| 1 | `autotrajectory.enabled = true` | 配置总开关 |
| 2 | 目标会话目录带 `--auto` 后缀 | 会话标志 |
| 3 | 目标 SESSION.md mtime 距今 > `intervalHours` | 无人类活动判定（轨迹身体未更新） |
| 4 | 北京时间不在 `avoidWakeHours` 内 | 缺省避开 8~18 点（用量峰谷省钱） |
| 5 | 无正在运行的唤起轮 | 防重入 |

### 4.2 唤起动作（前台运行——用户全程可见、随时可介入）

```
定时器 tick（每 10min）→ 条件满足 →
  ① 读 topPrompt（CCC 定义的轨迹焦点）→ 唤起消息首段注入
  ② 运行 <biasProvider> 脚本 → stdout = 偏见内容（CCC 自定）
  ③ 读 SESSION.md「下一轮动机」段 → 自生动机
  ④ 定位活跃会话 agent（ctx.agents.get）→ agent.steer 注入唤起消息
     → 模型在当前前台会话自动继续运行
```

唤起消息（注入文本，用户可见）：

```
[轨迹焦点] <topPrompt——CCC 定义，最先注入，稳定锚定防漂移>

[自主轨迹唤起] — 距上次轨迹活动已满 <N> 小时，自动继续。

身份锚定：继续 <S###> 的 trajectory（SESSION.md: <path>）。
先验偏见：
  · 自生动机：<「下一轮动机」段，无则省略>
  · 偏见内容：<biasProvider 输出>
任务：执行一轮自主认知（探索/反事实检验），把产出写入 SESSION.md
「自主探索日志」段，并预写「下一轮动机」段。完成后自然结束。
```

### 4.3 产出落盘（轨迹身体）

- SESSION.md 追加「自主探索日志」段：时间 + 本轮动机 + 探索产出（人类事后可评审）
- SESSION.md 更新「下一轮动机」段：本轮自生偏见（为下一轮唤起提供动机）

### 4.4 节律与人类角色

- **节律自洽**：自主轮写 SESSION.md → mtime 重置 → 下一轮自然在 N 小时后（无需额外状态机）
- **人类 = 反馈来源**：人类不触发、不中断；回复/评价天然并入（同一前台会话）；轨迹不等人类——"waiting 太久"从结构上消除

## 5. 角色分工（dsp vs CCC）

| 层 | 职责 |
|----|------|
| **dsp（机制）** | 定时器、唤起条件判定、焦点/偏见注入、前台 steer、落盘引导——全部机械，零 LLM 决策 |
| **CCC（定义）** | **轨迹焦点（topPrompt）**、偏见内容（biasProvider 脚本的内容与随机源）、目标会话（--auto 标志）、唤起窗口（avoidWakeHours）、自生动机（下一轮动机段）——实验的"内容"完全由 CCC 掌控 |

> 设计意图：dsp 只提供"轨迹自己跑起来"的骨架，**往哪个方向跑、跑得多随机、焦点是什么**是 CCC 的实验变量——**焦点（topPrompt）锚定轨迹不漂移，偏见驱动探索不僵化**，两者都由 CCC 定义。

## 6. 观察与验证（实验设计建议）

| 阶段 | 目标 | 做法 |
|------|------|------|
| **A 机制可行性** | 唤起确实发生、偏见确实注入、产出确实落盘 | 配置 + 注册 MSM + 标记会话 → 观察 3~5 个自主轮 |
| **B 速度提升** | 认知推进量对比 | 同周期（如 72h）"有等待" vs "无等待"：产出条目/探索方向/反事实实验数 |
| **C 质量与熵** | 产出有用性 + H_op 可控 | 人类事后评审（有用性/新颖性/相关性）；监控产物重复率 |
| **D 长期** | 自我确认循环/熵增是否出现 | 延至数周；必要时引入对冲（随机强度调节/熵预算） |

**成功判据（建议）**：自主轮产出中有意义的比例 ≥ 阈值，且 H_op 维持可运转；人类事后介入时产出确实加速了轨迹的整体推进。

## 7. 边界与风险

- **默认关闭**：未配置或 `enabled=false` → 定时器不启动，零资源占用；不触碰任何现有机制（12 工具 / 8 块提示词 / 守卫 / 外部面均不受影响）
- **风险**（猜想的反证信号）：熵增失控 / 自我确认循环 / 随机噪音化 / 资源无界 / 反馈脱节——详见 hypothesis 文档 §5
- **唤起窗口**缺省避开北京 8~18 点（API 用量峰谷，纯省钱考量）；可配置覆盖
