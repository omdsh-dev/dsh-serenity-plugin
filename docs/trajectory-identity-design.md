## 0. 一句话

**当前 ACC 里没有"轨迹"这个实体的本体记录**——所有轨迹级事实（它是谁、它的权威载体是哪一个、它的日志多大、它该不该重建）都只能从**载体级记录**派生。
因此每个写入路径都得各自维护同一条轨迹级不变量，补丁必然漏（**§1.1 有实测证据**）。
本设计做**一个动作**：**给轨迹建本体记录（以轨迹为键），并把所有轨迹级事实收敛到它**；在此之上，把"载体轮换"与"回收"升为一等动作/政策。
命名（§4）不是装饰，而是这次动作在**语言层**的同一件事：**把轨迹的身份边界显式编码**（CCE §2.3 要求）。

## 2. 理论起点（三条轴）

### 2.1 CCE 的立场（**容器自有的理论，最高优先级**）

CCE §2.3「认知身份边界」直接给出了**三条工程判据**——本设计用它当验收标准：

> A Cognitive Identity Boundary must be: **① Stable enough** to serve as a persistent referent；**② Permeable enough** to admit new information, agents, and reorganization；**③ Explicitly encoded** —— an implicit boundary ("we all just know what this project is") **cannot be engineered**; it must be externalized as a defined structure.

- **① 稳定** ⇒ 名字/身份**不随载体更换、rebuild、压缩而变**。
- **② 可渗透** ⇒ 身份**不编码易变的范围**（"dsh-serenity-plugin 长期维护"是描述，不能当名字：范围一变就失真）。
- **③ 显式编码** ⇒ 🔴 **当前轨迹的边界只由"编号 + 目录描述"隐式承载，且没有本体记录 ⇒ 按 CCE 就没被工程化**。这一条是本设计的正当性来源，不是修辞。

另两条同源的 CCE 命题：
- §2.3：「语言不只是描述边界，**语言参与创造边界**」⇒ **类 1 改词不是润色，是边界工程的第一步**（给实体起名 = 让它成为可被工程化的对象）。
- §2.2：`C(tₙ) = f(C(tₙ₋₁), Δₙ)`，**轨迹 = CCE 的基本分析单元**（取代离散的"交互/会话"）⇒ 命名的对象是**轨迹**。
- §5.2：**Kolmogorov 复杂度 = 重建成本下界** ⇒ 名字的信息学定位见 §2.2。
- §7.6 开放问题 #8：「**When does a cognitive entity cease to be 'the same thing'?**」——CCE 自己列为**未答**；本设计是它的一次工程化回答。

**信息论侧的两句总结（写进设计判据）**：

> **同一性** = 一个能在换载体后**依然把差异传下去**的**可纠错模式**；它的载体无关性**不是天然的，是冗余买来的**。
> **名字** = **指向共享索引的、抗噪的短地址**——不是最短描述（K 不可计算），不是哈希（哈希不承担人类信道），也不是空洞标签（空洞是指针的本性，不是缺陷）。

## 3. 统一方案（**范围层 + 方案层**）

### 3.1 核心动作：给轨迹建本体记录（Registry）

新增**一条以轨迹为键的持久记录**（建议仍住 `AGENT_SESSIONS/`，成为该目录的**索引**，与 `.bindings.json` 同族但**翻转键**）：

```
AGENT_SESSIONS/.trajectories.json        # v2 schema（或 .bindings.json 升 v2）
{
  "version": 2,
  "trajectories": {
    "<dirName>": {                       # ← 键 = 轨迹（= 磁盘唯一锚，已存在，无需新造 id）
      "label": "S142",                   # 机器展示码（沿用）
      "name": "…",                       # 🔴 人类名（§4；唯一真相源仍在 SESSION.md frontmatter，此处为缓存）
      "createdAt": 1787...,
      "carriers": [                      # ← 轨迹级事实，收敛在此
        { "sessionId": "session-b98276fe…", "at": 1789743855135, "action": "rebuild",
          "authoritative": true,         # 🔴 显式字段，不再靠 max(at) 派生
          "supersededAt": null, "lastKnownLogBytes": 72345678, "state": "live|cold|dead" }
      ],
      "rotation": { "epoch": 1, "lastRotatedAt": ... },   # §3.3
      "rebuild":  { "queued": false, "summary": null }    # §3.2 承接 pendingRebuilds
    }
  }
}
```

**三条设计判据**：
1. **键 = 轨迹**（`dirName`，磁盘唯一、已存在、与 SESSION.md 同址）⇒ 主体与键一致；
2. **单一写入路径**：所有 writer 一律经 `bindCarrier(trajectory, carrier, action)`——该函数**内联**"标记其它载体 superseded + 更新 authoritative + 清理悬空"三条不变量 ⇒ **不再依赖各 writer 记得调用**（§1.1 的病根被结构性消除）；
3. **本体记录只记"模式与索引"，不复制内容**：叙事本体仍是 `SESSION.md`（单一真相源），registry 只记身份与载体索引（避免第二真相源）。

### 3.2 键错位的逐项归位

| 现状 | 归位后 |
|---|---|
| `.bindings.json`（载体键，只增） | `.trajectories.json`（轨迹键，载体为**列表项**，每项有 `state`/`supersededAt`） |
| `pendingRebuilds`（载体键 + 仅内存，`rebuild.ts:320`） | 落进 registry 的 `rebuild` 字段（**轨迹级 + 持久**）⇒ 重启不再静默丢排队意图 |
| `compactionStates`（`keeper.ts:180`，量的却是 SESSION.md 体积） | **键改轨迹**（主语一致）；`mdPathCache` 同理 |
| keeper 计分 `trackers` / `rebuildReminderStates`（`keeper.ts:316/325`） | 语义上确属载体级（"本载体累计工作量"）⇒ **键可留**，但必须**接进 `cleanupSessionState`**（消除只增） |
| `bootstrap.anchoredSessions`（`bootstrap.ts:249`） | 接入同一清理路径（低危但同族） |

### 3.3 载体退役：把"轮换"升为一等动作（承接病根 C）

**为什么必须做**：(a) 的 A2 形态（自动 rebuild）被否决**不等于需求消失**——宿主日志只增、`rebuild` 不换 id/不换文件 ⇒ **唯一能重置日志的动作就是换一个 dsh 会话 id**，而 ACC 至今没有这个动作。

**方案**：新增轨迹动作 **`rotate`（换载体，不换轨迹）**——
1. 建**新** dsh 会话（新 id ⇒ 新日志文件、体积归零）；
2. 绑定到**同一**轨迹（SESSION.md 原位不动 ⇒ 认知连续）；
3. 旧载体标 `supersededAt` + `state: retired`（保留沿革，不再参与唤醒）；
4. 注入交接锚点（复用 rebuild 的锚点协议，但**不清空**任何东西）。
**与 `rebuild` 的区别**（关键）：`rebuild` = 清空**当前载体**重用（同一 id、同日志文件继续增长）；`rotate` = **换一个新载体**（日志可退役）。二者互补：rebuild 治"上下文窗口"，rotate 治"日志体积/载体退役"。

**skiff 侧**（加剧形态）：载体 id 是 `sha256(userId)` 的纯函数（`weixin-route.ts:43-45`）⇒ 无人工路。方案：id 加 **epoch 后缀**（`skiff-weixin-<hash>-e2`），epoch 存 registry；**同一用户长期同一轨迹，载体可轮换**。

🔴 **顺序铁律（Landauer，§2.2）**：`rotate` 与 `rebuild` 一律 **先复制、后擦除**——
① 先把模式落到 `SESSION.md`（可逆、近零成本）② 再新建/清空载体 ③ **最后**才退役旧载体。
**反序（先清空再想）＝ 把唯一不可逆的一步放在最前**，属硬约束，应写成测试（断言：任何清除动作之前必有一次落盘）。

### 3.4 回收：把"保留策略"变成显式政策（承接病根 B）

统一一条判据：**凡 append-only 台账，必须声明保留策略**（谁、多久、丢什么、丢之前先归档到哪）。

**两条裁剪判据**（来自 §2.2，把"删不删"从口味问题变成可判定问题）：

| 判据 | 出处 | 怎么用 |
|---|---|---|
| **Bateson 判据**：同一性 = **仍能改变下一轮行为**的那组差异 | Bateson 1972 | 裁剪前问一句："**它还改变下一轮行为吗？**" 不能 ⇒ **裁掉不损失同一性**（这是"可以删"的**证明**，不是借口） |
| 🔴 **Shannon 反判据**：冗余是**抗噪预算**，不是啰嗦 | Shannon 1948 | **不得以"精简"为名删掉重述的约束与决策理由**——它们是在 rebuild/rotate 的**有噪信道**上传输轨迹的纠错码。⇒ **本设计推翻一种常见做法**：把 SESSION.md 压成"只有结论+索引"会**降低**跨载体重建的保真度 |

⇒ 两条合起来才是完整政策：**该删的按 Bateson 删（不能再造成差异的），该留的按 Shannon 留（承载抗噪冗余的）**。
首批落地：`wake-registry.json`（`delivered`/`missed` 超过窗口即归档/丢弃；当前 253.8 KB 且只增）、registry 里的 retired 载体、keeper 两张表。

### 3.5 词汇层（类 1）：改名 + 注入文案

与上述同源、但可**独立分批**（低风险）：
`ActiveSessionInfo`/`activeStore`/`DEFAULT_SESSION_SCOPE`/`readActiveSessionMd`（`trajectory-ops.ts:332/339/368`）、`resolveActiveSessionInfo`/`sessionBlock`（`seams/system-prompt.ts:420/439`）、注入文案的 `Session-first`（`:216`）与 `session tracking`（`seams/context.ts:59/69`）。
**边界不变**：**`SESSION.md` 文件名不动**（历史命名 + 全仓引用）。

## 4. 命名：让轨迹有名字（**owner 的直接诉求**）

### 4.1 定位：两层身份，各司其职

| 层 | 承担 | 形态 | 信息论角色 | 哲学角色（已引证） |
|---|---|---|---|---|
| **编号** `S142` / `dirName` | 机器寻址、排序、唯一性 | 定长、可排序、**不给人类念** | **地址**（唯一、最短、无含义） | **idem**（相同性）——利科 |
| **名字** `…` | 人类称呼、注入文案、面板 | 1~3 字、可发音、有含义 | **短描述**（共享码本，参考成本≈0） | **ipse**（自身性／叙事身份）——利科；丹尼特「叙事重心」的抓手 |

**判据（写进未来的护栏测试）**：**名字不随载体更换 / rebuild / LOGBOOK COMPACTION 而变**（CCE ① 稳定）；
**名字不编码会漂的范围**（CCE ② 可渗透）；**名字必须写在文件里**（CCE ③ 显式编码）。

### 4.2 存哪、怎么解析（**零破坏路径**）

- **唯一真相源 = `SESSION.md` 顶部 frontmatter 的 `name:` 键**（与 `skills:` 同址——身份与声明同处轨迹本体，随目录走，ACC 只读）。
  🟢 **前向兼容**：现行解析器**只认 `skills:`、未知键一律忽略**（`trajectory-skill-injection.md:42`）⇒ **先加名字不破坏任何东西**，可分批落地。
- **resolution 插一层**：`findSession` 现有三步（精确目录名 → `S###` → 唯一模糊，`trajectory-ops.ts:152-173`）**在 `S###` 之后插"名字精确匹配"**；registry 作缓存加速。
- **会话标题**：`S###` **必须保持首 token**（`resolveSessionByTitle:511` 取 `'-'` 前首段作 code），故标题可扩为 `S142-<名字>-YYYY-MM-DD-<概括>`——**解析兼容**（已核实）。
- **压缩护栏扩展**：compaction 提醒现要求"保留 frontmatter 原样"（`keeper.ts` 的 `frontmatterGuard`）⇒ 文案补一句**点名 `name:`**（与 `skills:` 同款，单一文案两处共用）。
- **唯一性**：CCC 内唯一（`create`/`use`/改名时校验），冲突**报错并给候选**，不自动改名。

### 4.3 隐喻槽位（**按 M-1 这是必须补的**）

`docs/metaphor-domain.md` 的三层骨架里：Ship（容器本体）/ Voyage（生命周期：启航检查→Logbook→Theseus）/ Crew（协作）。
🔴 **轨迹（D58 起的一等实体）在隐喻域里没有槽位**——而 M-1 规定"**每条隐喻必须映射一个协议约束或机制，无映射的隐喻 = 修辞装饰 = 不允许**"。
⇒ 给轨迹命名**不是装饰**，而是**补一个 M-1 缺口**：先给轨迹一个隐喻槽位，名字才有所依托。

**候选槽位**（供 owner 选，均落 **World 层**，满足 M-3「单一层级」）：

| 案 | 隐喻 | 映射的机制/约束 | 命名域 | 风险 |
|---|---|---|---|---|
| **A · 导航星**（推荐） | **Trajectory ↔ 导航星**：星不动，船在动；**一代代船员换班，都靠同一颗星定位** | CCE 身份连续性（跨载体不变的参照物）；信息论"定位 = 共享参照" | **星名**（天枢 / 摇光 / 心宿 / 天狼 / 参宿 / 织女 / 老人 …） | 部分星名生僻难打 |
| **B · 航次** | Trajectory ↔ 一次航程/航线 | 载体的更替 = 换班次 | 航线名（长风 / 信风 / 季风 / 洋流 …） | "航次"自带起止语义，与"长期不结束"张力 |
| **C · 呼号**（与既有实体同构） | Trajectory ↔ 船员呼号（**先例：skiff 角色已有人名"招财"**） | 多 agent 协作（CCE 5） | 人名式呼号（长风 / 知白 / 怀山 …） | 拟人化可能模糊"身份属于容器"的边界 |

**M-2 判据（每案都适用）**：名字**跟随轨迹**而不跟随载体；载体换了名字照旧 ⇒ 若观察到"名字随载体变"即违规。
**M-4**：三个候选都在**同一宇宙**（星舰/深空）内，不破坏"one starship, one voyage"。

### 4.4 命名动作（**owner 拍板，我们只给约束与候选**）

参照 specs §12.4 的先例（Induction 定名）：**先定"这个实体是什么/它在做什么"，再选词**；给候选对照 + 理由，由 owner 拍板。

**名字的约束清单**（候选必须全过）：
1. **长度与音节**：1~3 字（**≤2 音节**）；中文侧对应 Crockford 的"可发音"要求；
2. **抗噪**（工程侧调研结论，§2.2 卡片 8）：**避生僻字与严重同音字**——中文里"排除 I/L/O/U"的等价物是**排除易混字**；
   若名字需要**手抄或键入**（面板、命令参数），应带**校验位**或**分块书写**；
3. **不冲突**：与容器既有实体名不重复（宁静号 / 招财 / desk / 天工 / 舢板…）；
4. **不编码易变范围**（CCE ②）：描述会漂，名字不会；
5. **过 M-1~M-4**（隐喻域四条结构约束）。
6. 🔴 **声明 LoA**（Floridi，§2.2）：名字绑定在**轨迹层**（应当持续），编号绑定在**载体/机器层**——两者不得互相兼任
   （这正是"S142 累"的机制根源：**它同时在两个 LoA 上被使用**）。

### 4.5 三处补齐（评审自查所得）

1. **改名要留别名**：名字是 owner 的称呼，会改。若只存当前名，历史引用（旧笔记、唤醒条目、别的轨迹的消息）会解析失败。
   ⇒ registry 存 `name` + `aliases: []`（**只追加**）；`findSession` 解析时**主名优先、别名兜底**；**别名永不复用给别的轨迹**（莱布尼茨判据：可分辨性）。
2. **skiff 不用额外起名**：skiff 自动建的轨迹（`<role> skiff`）**默认名 = 角色名**（先例：`zhaocai` → **招财**）。
   理由：既有的角色名已经过 owner 使用验证，且"同一实体不该有两个称呼"。⇒ §6-2 的答案倾向：**所有轨迹都有名字，skiff 自动取角色名**。
3. **解析成本**（工程约束）：名字住在 `SESSION.md` frontmatter ⇒ 解析名字要读文件。
   - `findSession` 本来就要遍历目录 ⇒ 只在**前两步未命中**时才读 frontmatter，成本可控；
   - **注入路径（每请求）必须走 registry 缓存**（与既有 `mdPathCache` 同款 60s TTL），**不得每次读盘**。
