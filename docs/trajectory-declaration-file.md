# 轨迹声明面：`trajectory.json`

- 日期：2026-10-19
- 状态：**已实现**（v1.75.0；owner 裁 Q1／Q2）
- 归属：ACC（机制）｜内容：CCC（填什么）
- 相关：`docs/cro-design.md`（CRO 机制）、`docs/cognitive-trajectory-identity-design.md`（身份演进）

---

## 1. 一句话

**一条认知轨迹的"声明"只有一个文件**：`AGENT_SESSIONS/<轨迹目录>/trajectory.json`。
它装约束面、旧标识、机器绑定三件事——**因为这三件事的主语是同一条轨迹**。

## 2. 它取代了哪三个文件名

| 原文件 | 现状 | 为什么能并 |
|---|---|---|
| `trajectory-constraint.json` | 顶层键（`model` / `tools` / `msms` / `cognitiveTrajectory` / `systemPrompt*`） | 它本来就是"这条轨迹的配置" |
| `TRAJECTORY-UID` | `uid` 字段（**只读**） | 它是"这条轨迹的别名"，主语相同 |
| `cro-host-binding`（一行机器名） | `cro.host` 字段 | 它是"这条轨迹的 CRO 由哪台机器跑"，主语相同 |

三者**生命周期相同**（随 git 走）、**写入频率相同**（人改）、**都应该能被 diff**。

## 3. 为什么 `cro-wake-log` **不并**（owner 裁 Q1）

owner 原话：「**日志不要写 json，不合适，日志直接写纯文本 `.log` 就行**」。

判据两条，缺一不可：

1. **写入频率不同**：流水是**每次唤起尝试追加一行**；声明是**人偶尔改一次**。
   并进同一个 JSON ⇒ 每写一行流水都要**重写整份声明**。
2. **失效代价不同**：一次写坏，**同时丢掉**约束面与机器绑定（而那份流水本来就只留两日、可丢）。
   ⇒ **声明可人改、可 diff；流水高频追加、可丢** —— 两种东西不能同居一个写通道。

⇒ 流水的形态改为 **`cro-wake-log.log`（纯文本行）**：人类会 `grep` / `tail` 它，
且**单行损坏不该毁掉整档**（结构化 JSON 在这两点上都更差）。

## 4. 文件名族（**认族，不认当前叫什么**）

```
trajectory.json  →  trajectory-constraint.json  →  skiff.json
    （新，只写）        （v1.74 名，仍读）          （v1.71 名，仍读）
```

**任一存在即成立**，**顺序即优先级**。**写只写新名；旧文件永不自动删。**

### 4.1 为什么必须认族（本仓已两次栽在这上面）

失效形态是固定的：**上游改名、下游写死旧名** ⇒ 症状是「配置没生效」，真因是「文件名对不上」，
**两者在读数上完全不像**（一个像权限问题，一个像路径问题）。
⇒ **判据：再改名只往族里加一项。**

### 4.2 🔴 `cro.host` 更硬：必须**两代并读**，不许硬切

绑定声明要跟着轨迹**走到第二台机器**，在那里被判成「**绑给了别人**」而**正确地不跑**。

硬切之后，第二台机器读到的是**「没绑」**——

> **表面结果相同（都不跑），但判据退化**：失去"明确绑给别人"的可诊断性。

⇒ 新字段 `cro.host` 优先，旧文件 `cro-host-binding` 回落。**两条路都必须能读。**

## 5. 读取侧的优先级（三处各自实现）

| 能力 | 新（声明文件） | 旧（回落） | 合并判据 |
|---|---|---|---|
| 约束面 | `trajectory.json` 顶层 | 族内旧名 | 族内**第一个存在者**胜 |
| 轨迹标识 | `uid` 字段 | `TRAJECTORY-UID` 文件 | 声明面有**合法** `uid` ⇒ 用它 |
| CRO 机器绑定 | `cro.host` 字段 | `cro-host-binding` 文件 | 声明面有**合法** `cro.host` ⇒ 用它 |

⚠️ **"合法"是判据的一部分**：形态非法的 `uid` / 空串的 `cro.host` **按"没给"处理**，
⇒ **回落到旧载体**，而不是"当成绑了空名"或"当成没有标识"。

## 6. 字段名的一处更正（相对早期方案书）

早期方案书把旧标识字段写作 `code`。**实现改成 `uid`**，理由：

`code` 在本仓已有一个**更窄、更硬**的含义 —— 目录名里那个固定位置的**轨迹编码**
（`parseTrajectoryCode`），它是**派生的结构**，不是可选项。
同一个词在一个 JSON 里表示两件事，正是本轨反复抓的「名字会撒谎」。
⇒ **`code` 留给结构，`uid` 给旧别名。**

## 7. 迁移纪律（**时机**判据）

⚠️ **不能先改磁盘**：线上跑的是旧版本，它**只认旧文件名**。此刻改名 =
**当场卸掉那条轨迹的全部约束**（权限面静默消失）。

⇒ **迁移 = 新版本装机并重启之后**，与"删旧 `skiff.json`"**同一个窗口**。
在那之前，旧文件必须留着。
